## 2. Technology stack

| Layer | Choice | Version | Why |
|---|---|---|---|
| Contracts | Solidity, Foundry | 0.8.28, Foundry 1.9.0 | Fast fuzz and invariant testing; `forge script` for deployment |
| Contract library | OpenZeppelin | 5.6.1 | Audited ERC-20, 721, 4626, AccessControl, EIP-712 |
| EVM target | `cancun` | | Supported on Arbitrum and Base |
| zk | circom, snarkjs, circomlib | circom2 0.2.23, snarkjs 0.7.6 | Groth16: small proofs, a verifier that fits the 24 KB limit, about 320,000 gas |
| Off-chain | Python | 3.12 | web3 7.16, FastAPI, scikit-learn |
| Runtime | Node | 22 | Required by snarkjs |
| Local chain | Anvil | Foundry 1.9.0 | Time travel, and forks of live testnets |

**Why Groth16 over EZKL.** The report names EZKL. Groth16 was chosen for its small verifier and low gas, which matter for real L2 deployment. Its cost, a per-circuit trusted setup, is reduced here by making model weights private inputs, so the setup survives model changes. EZKL is the natural route if a model outgrows a hand-written circuit.

Sizes are deployed bytecode; the EVM limit is 24,576 bytes.

### Signed message formats (EIP-712)

Each domain uses version `"1"`, the chain id and the verifying contract. The Solidity type hash and the Python field list must match exactly; `petahour/marketplace.py` holds the Python side.

| Message | Signed by | Domain name |
|---|---|---|
| `Order` | The client | `Petahour DvP Escrow` |
| `MintPassport` | Federation | `Petahour Compute Passport` |
| `Attestation` | Federation | `Petahour Proof of Delivery` |
| `TelemetrySeal` | The host's sealed key | `Petahour Proof of Delivery` |
| `TCPIPublish` | Federation | `Petahour TCPI Oracle` |
| `FederationRuling` | Federation | `Petahour DvP Escrow` |

### Wallets

`petahour/chain.py` derives every role from one mnemonic by index: 0 is the Petahour admin, 4 is the Labs admin, 5 to 7 are federation signers. Local runs use Anvil's public development mnemonic, whose keys must never hold real value.

## 5. The zk pipeline

```
scripts/zk_build.sh
  1. python -m petahour.zk_model        train on simulated telemetry, quantize to integers
  2. circom2 delivery_score.circom compile to R1CS and wasm
  3. snarkjs powersoftau           phase 1, 2^13
  4. snarkjs groth16 setup         phase 2, proving key
  5. snarkjs zkey export           verification key and Groth16Verifier.sol
```

The repository ships with these artifacts built, so `make zk` is needed only if you change the circuit. It writes a new verifier, so contracts must be redeployed and the test fixture regenerated. The Makefile target does the fixture step.

**Changing the model needs none of this.** Weights are private inputs bound by hash:

```bash
python -m petahour.zk_model
python -m scripts.gen_fixtures
```

Then call `setModel` on a deployed adjudicator, or redeploy.

## 6. How to change things

### Change the fees

The schedule is in `petahour/config.py`, copied from the financial model, and the deployment takes the launch-year rates from it. On a live deployment, step the rate down by calling `setParams` with new `buyerFeeBps` and `sellerFeeBps`. Each side is capped at 10%, and open trades keep the rate they opened at. Change the Passport price with `setFee` on `ComputePassport`. `make price` prints the schedule. Labs' curator, origination and licence rates are in the same file, and are fixed at deployment.

### Rename again

The name appears in strings that are signed, so change contracts and Python together, then run `make test`.

| Where | Strings |
|---|---|
| `ComputePassport.sol` | Token name and symbol `PHPP`; EIP-712 name |
| `ProofOfDeliveryOracle.sol`, `DvPEscrow.sol`, `TCPIOracle.sol` | EIP-712 names |
| `ComputeCreditVault.sol`, `GPUWarehouseReceipt.sol` | Token names and symbols `phSR`, `phJR` |
| `petahour/marketplace.py`, `petahour/scenarios.py` | `chain.domain("Petahour ...")` calls |
| `test/Base.t.sol`, `test/labs/Labs.t.sol`, `test/invariant/` | Domain strings used for signing |

Solidity identifiers such as `TCPIOracle` are internal and can wait. "TCPI" itself does not collide.

### Connect the real Silicon Data API

Replace the paths and field names in `SiliconDataClient` in `petahour/marketdata.py`, and point it at the real base URL. Nothing else changes. Check your licence first: it may not cover redistribution.

### Connect the real NVIDIA NRAS

Point `tee.request_attestation` at `https://nras.attestation.nvidia.com`, and replace `SimulatedHost.evidence` with real evidence from NVIDIA's SDK on a CC-enabled host. `verify_eat` already follows the real flow and JWKS. Add a CPU TEE quote carrying the sealed key, because a GPU report alone does not bind the GPU to a VM.

### Move to real Morpho Blue

Create a Morpho market with `GPUReceiptWrapper` as collateral, `TCPIPriceAdapter` as oracle and a 62.5% LLTV. The deployment already uses that LLTV and Morpho's incentive at it, so the risk settings carry over. Add the Morpho contract to the Labs allow-list, so it can hold the restricted token. Point `ComputeCreditVault` at it through a small wrapper that keeps the running total of bad debt, which Morpho does not. A plain MetaMorpho vault has no waterfall, so it cannot replace this one without losing the first-loss return.

### Add a SKU

Add it to `SKUS` in `petahour/config.py`, and deploy another wrapper, adapter and market for it. Orders already carry the SKU.

### Tune parameters

Escrow parameters are in `script/Deploy.s.sol`, and can be changed live with `setParams`. Fees and index parameters are in `petahour/config.py`.
